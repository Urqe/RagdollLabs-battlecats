## Minimal shared design

- Use plain immutable level definitions with stable IDs, displayed titles, and a fresh mutable state on every start or replay. Pass the selected definition into game creation and rendering. Keep the ES modules, Canvas, and one animation loop. Feature-specific behavior belongs in small shared functions called by the simulation update when the level has that feature.
- Let geometry describe the logical viewport, cannon bounds, lane and terrain shape, gate and target footprints, frontline limits, castle breach point, and enemy entry and cutoff. Keep hit geometry available without Canvas and let rendered signs and wood use the same placements. Use stable target IDs for progress, visuals, HUD, effects, and unlock destinations. Resolve a shot against reachable surfaces in travel order, consuming it once. Preserve the existing behavior when a sibling in the same volley opens wood.
- Put initial armies, reinforcement growth and cap, pressure parameters, march timing, gates, and barricade durability in data. An open gate multiplies each crossing projectile and still produces a marching formation. Keep supply access separate from the remaining health or unit count. Use the shared clear-and-hold objective and breach rule for the first two levels, with their locations supplied by the definition. Add a new objective rule only when a validated level requires it.
- Add one support definition for the Purrapult with its barricade, crew position, targeting rule, reload, flight time, and damage parameters. A simulation event starts the arc, and the simulation update resolves the impact once at its scheduled time. Begin with a small, deterministic target window inferred from the engaged red aggregate and the current front. A target window is a simulation approximation. Rendered red cats remain representative. If that approximation cannot explain the splash clearly, prototype one modeled reserve band before considering a spatial redesign.
- Give the renderer level geometry, palette, and bounded effect data through existing simulation events. Keep cosmetic randomness independent of any future simulation RNG. Reuse sprite and terrain caches, the muted-by-default sound preference, and the current logical resolution where practical. Clear transient shots, animation tails, sounds tied to the battle, and pending impacts when changing levels or restarting.
- Put a minimal selector on the existing menu, outside the battle interaction area. Default to Level 1 for a fresh visit and keep replay on the same level. Keep Level 1 directly accessible after completing later levels. Begin with both playable levels available for feedback, then revisit unlock rules using playtest evidence. If saving progress is useful, store completed stable level IDs and the last selected ID locally. Treat missing, corrupt, or unavailable storage as defaults, ignore unknown IDs, and preserve the separate sound preference. Keep live runs out of persistent storage.

## Migration for Milestone 7

1. **Pin Level 1.** Keep the [committed strategy evidence](level-1-balance.md#deterministic-results) and browser playthroughs as the baseline. Extract its existing numbers and locations into one definition without retuning. Compare outcomes, gate timings, pressure reversals, supply cutoff, the final-elimination trigger, and touch behavior. Keep screenshots and clips as visual references.
2. **Replace indexing where Level 2 needs it.** Make gate and barricade rendering, HUD, and projectile targeting use the same IDs and footprints. Leave one front. Test closest intersections, missed and direct shots, gate unlock persistence, restart isolation, and existing count and travel behavior through normal entry points.
3. **Add artillery and a selector.** Prototype a single support object behind wood and bind it to the same cannon-volley trade-off. Create Level 2 as the second definition and route level select, restart, and back navigation through the same browser shell. Check that starting another level creates fresh state and that storage failures preserve access.
4. **Prove both levels before further extraction.** Run deterministic strategies at 30, 60, and 120 Hz for Level 1 and representative Level 2 approaches. Test reload cadence, target eligibility, once-only impacts, bounded casualties, victory with a final artillery hit, and no hits after defeat or restart. Run Chromium touch and mobile-emulated WebKit playthroughs, review HUD-hidden motion, and measure responsiveness on a physical iPhone when available.

The second front, armor rules, and commander effects can wait until their briefs justify them. Use measured duplication and playtest problems to decide what becomes shared.
